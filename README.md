# Pi 原生 CRM（内部研发）

本项目以 CRM 作为业务事实和状态空间，以 Pi 智能体内核执行开放目标。重点是验证智能体如何读取业务上下文、调用受控工具、协作判断并安全地改变 CRM 状态，而不是建设功能齐全的商业 CRM。

> 当前处于内部研发与验证阶段，不具备无人值守生产运行条件。关键业务结论和对外动作仍需人工把关。

## 当前状态

以下信息截至 2026 年 10 月 3 日。主分支已有能力与评审分支中的开发进展分别列出；评审分支不代表已经发布或部署。

### 主分支已有

- 智能体工作台位于 `/app/ai/workbench`，可选择内置智能体、CRM 对象和任务，查看运行事件、工具调用、状态变化与评测结果。
- 新组织可幂等安装四个内置智能体：CRM 情报员、销售运营智能体、客户沟通智能体、CRM 主管智能体。内置原件不可直接编辑，可复制后定制。
- CRM 主管智能体可并行调用只读专职智能体并汇总分析；子运行具有持久化状态、执行租约与重试隔离，业务写入仍由父运行控制。
- 工作台已支持持久化事件、断线续读、取消、预算限制、对外动作的人工确认，以及批准后的恢复执行。
- 评测包含确定性安全检查、运行轨迹检查、结构化证据声明、回归样例和可选的真实模型语义评审。语义评审不能覆盖更严格的确定性结果。
- 知识检索已有统一接口；没有已发布的知识材料时会报告证据缺失，不会将空结果伪装为有依据的回答。

一次[真实模型运行](docs/testing/multi-agent-eval-real-run-2026-09-28.md)中，三个专职智能体完成并行分析，调用 CRM 工具 8 次，形成 56 条结构化证据声明；确定性评测仍要求人工复核。这证明相关链路可运行，不代表业务结论已可靠或系统可投入生产。

### 评审分支验证中，尚未合入主分支

- 已修复第三方 Memory 未配置时 CRM 人工确认记忆被隐藏的问题：SQL 保持事实源，Mem0 仅用于可选排序。独立记忆覆盖评测能识别漏读，已保存的语义评审可只读回放。
- 已提交[真实模型修复前后记录](docs/testing/agent-services-real-run-2026-10-03.md)和[脱敏录制](docs/testing/fixtures/agent-services-real-2026-10-03.json)。原录制的真实 Judge 为 92 分，但总评仍待复核；后续[本地三服务联调](docs/testing/local-agent-services-connected-2026-10-03.md)已验证 Mem0 真实检索/删除、WeKnora 生成与 CRM 引用、Langfuse Trace/Eval 落库回读。该次只读运行引用 4 条 Wiki 证据，真实 Judge 86 分、总评 81 分待复核，不代表业务已完整验收。
- 商机持续任务、结构化结果提交、证据核验、跨运行预算与取消保护已有本地实现和定向测试；尚未完成完整业务验收。
- 负责人可在任务等待复核、客户回复或动作审批时补充方向，并使待审旧提案与草稿失效。自动商机写入已有方向版本保护，但运行中即时转向、模型消费确认与完整恢复链路尚未闭环。
- 飞书内部协作的身份映射、一次性成员绑定、消息队列和回复后续跑已有本地实现与定向测试；应用安装与真实飞书租户端到端验证尚未完成。
- 结构化报价与交期可固定为一版明确确认请求；只有审批原文、发送回执、同渠道完整确认码以及已验签回调与 CRM 消息的逐条绑定都吻合，才报告条款获得渠道明确回复。默认未签名 WAHA Core 不能通过这项验收；尚未完成真实客户渠道联调，不等于法律身份或任务全部自由文本条件已验收。

首次[系统全面验收](docs/testing/system-acceptance-2026-10-03.md)结论为**不通过**：构建与静态检查通过，三个本地服务及新运行的 Trace/Eval 落库回读通过；但真实多智能体没有最终答复（Judge 5 分），单智能体错误降级了已确认记忆（Judge 74 分），全量单测 5 项失败、数据库不变量 37 项失败。该报告及[脱敏结果摘要](docs/testing/system-acceptance-2026-10-03.json)保留为修复前基线；当前修复结果见下方复验报告，不能只依据较早的成功联调记录判断系统质量。

后续[修复复验](docs/testing/system-acceptance-fixes-2026-10-03.md)已修复累计用量误计数、确认记忆契约、数据库配置名、隔离/隐私证明、中文登录/MFA、凭据列表、403 语言和迁移后的注册邮件链路。全量单测 1,323 个文件通过（12,916 项通过），全量数据库 266 个文件通过（2,229 项通过），关键浏览器 28/28 及受控辅助自治 1/1 通过；构建与静态检查通过。真实记忆查询已完成、Judge 92；多 Agent 已有最终报告及 7 条 Wiki 证据、Judge 80，但总评仍待业务复核。两条新运行的 Trace 与分数已在本地 Langfuse 实际回读；既有 expected fail/skip、未覆盖场景与剩余边界见复验报告，不能据此宣布无人值守生产可用。

## 本地运行

需要 Node.js 22 或更新版本、pnpm，以及已配置的本地数据库和服务。复制环境变量模板并填写本地配置后运行：

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

访问地址以终端输出为准。运行真实智能体需在系统内配置有效的模型凭据；发送消息还需配置相应渠道。不要提交密钥或本地环境文件。

查看无需密钥的真实录制演示：运行 `node scripts/serve-agent-demo.mjs`，打开 `http://127.0.0.1:3008/#/app/ai/workbench`，点击“真实模型录制”。录制不会再次调用模型或执行工具；其他交互场景有明确的本地模拟标识。

可选的贡献与安装指引在 `.agents/skills/`；Codex 可使用 `$pi-native-instalar` 调用安装指引。内部开发请先阅读 `AGENTS.md` 和相应仓库规则。
