# Pi Native CRM

> 团队内部研发项目。以真实 CRM 为业务状态空间，验证智能体如何读取、判断并安全地操作业务数据；当前不具备无人值守生产运行条件。

## 项目定位

CRM 保存联系人、会话、商机、任务、知识和组织记忆等业务事实；Pi Agent Core 负责智能体执行循环。智能体通过受控工具读取或修改 CRM，不能直接访问数据库。项目重点是工具权限、预算、人工确认、执行恢复、事件回放和结果评测，而不是扩张传统 CRM 功能。

## 当前项目状态

以下状态截至 2026 年 9 月 30 日。GitHub 主分支与开发机上的未提交改动分开说明；两者都不代表已经生产部署。

- 已有可运行的智能体工作台：选择内置智能体与 CRM 对象，输入任务，并查看运行事件、工具调用、业务状态变化和评测结果。入口为 `/app/ai/workbench`。
- 新组织可幂等获得四个内置智能体：CRM 情报员、销售运营智能体、客户沟通智能体和 CRM 主管智能体。内置原件锁定，可复制后定制。
- CRM 主管智能体可并行调用三个只读专职智能体，再汇总结果。子运行具有持久化状态、执行租约和重试隔离；CRM 写入仍由父运行控制。
- 工作台运行已接入持久化事件、断线续读、取消、预算控制、外部动作的人工确认，以及批准后的恢复执行。
- 评测包含确定性安全与轨迹检查、结构化证据声明、固定回归样例和可选的真实模型语义评审。语义评审不能推翻更严格的确定性判定。
- 知识检索已有统一接口；没有已发布知识源时，系统会明确报告证据缺失。

一次真实模型验证中，三个专职智能体并行分析，CRM 工具调用 8 次且无工具错误，生成 56 条结构化证据声明。确定性评测要求人工复核；即使语义评审给出“通过”，最终仍保持人工复核。该结果只证明流程可运行，不证明业务结论正确或系统已适合生产使用。详见[真实运行记录](docs/testing/multi-agent-eval-real-run-2026-09-28.md)。

## 本地开发中，尚未推送

- 商机持续任务、结构化结果提交、证据核验、跨运行预算与取消保护已有本地实现和定向测试。负责人可暂停或恢复客户发送，并在任务等待复核、客户回复或动作审批时补充新方向；待审旧提案与草稿会失效。这些代码尚未推送，也未完成完整业务验收。
- 飞书内部协作的身份映射、加密消息队列、问题确认和回复后续跑路径已有本地实现及定向测试；尚未在真实飞书租户完成端到端验证，不能视为可用的生产渠道。
- Pi 运行时已接入转向消息端口并有定向测试，但负责人新指令在商机持续任务中的持久化、写入栅栏和“模型已消费”确认尚未形成完整闭环；不能把消息已排队当作转向成功。
- 飞书应用安装与成员绑定、审批卡片、企业微信接入，以及外部动作后的独立结果核验仍待完成。
- 演示组织没有已发布的知识库材料；真实政策依据和知识证据覆盖仍需补齐。
- 还需要工作进程强制退出后的端到端恢复测试、更多模型与服务商的兼容性测试，以及人工标注的长期评测集。
- 现阶段必须由人复核关键业务结论；真实模型测试只验证过部分链路，不能推断所有 CRM 场景均已可靠。

## 本地运行

需要 Node.js 22 或更新版本、pnpm，以及已配置的本地 Supabase/Postgres。复制环境变量模板并填写本地配置后启动应用：

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

启动地址以终端输出为准，通常是 `http://localhost:3000`。运行真实智能体需要在 CRM 中配置有效的模型凭据；发送消息还需要相应渠道。请勿将密钥或本地环境文件提交到仓库。

## 代码入口

- `lib/agent-runtime/`：产品级运行时接口及 Pi 适配。
- `lib/ai/agents/`：内置智能体、协作执行、工具策略和持久化运行。
- `lib/ai/evals/`：运行评测与语义评审。
- `lib/ai/knowledge/`：知识检索与证据接口。
- `app/app/ai/workbench/`：智能体与 CRM 交互工作台。
- `supabase/migrations/`：数据库迁移。

本仓库用于内部研发，不以公开发行或商业 CRM 功能完备为当前目标。仓库包含继承代码，仍须遵守 [MIT 许可和原版权声明](LICENSE)；提交历史的整理不改变该义务。
